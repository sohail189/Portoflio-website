The Problem

Information about tourism in Pakistan is scattered, and general-purpose chatbots hallucinate

Anyone researching travel in Pakistan has to piece together answers from dozens of blogs, forums, and outdated pages. General-purpose chatbots can answer confidently but are prone to making up details about lesser-known destinations, since they have no grounded source to check facts against.

The goal was to build an assistant that answers tourism questions the way a well-read local guide would — accurately, and only from a trustworthy, curated source of information rather than from memory alone.

My Approach

Grounding every answer in retrieved context

Instead of relying on a language model's raw knowledge, I built a full retrieval-augmented generation pipeline so every answer is backed by real, retrievable source text.

  • Curated and structured a knowledge base covering Pakistani destinations, history, culture, and practical travel information, then split it into semantically meaningful chunks.
  • Generated embeddings for each chunk and indexed them in ChromaDB, so the system can pull the most relevant passages for any question in real time.
  • Used LangChain to orchestrate the retrieval step and pass the retrieved context, along with the user's question, to a Groq-hosted LLM for fast, grounded response generation.
  • Built an interactive Streamlit interface so users can ask free-form questions and get conversational, source-grounded answers without needing to know how RAG works under the hood.

The most important design decision was refusing to let the model answer from anything but the retrieved context. If the knowledge base doesn't contain relevant information, the system says so instead of guessing — that single rule is what keeps hallucination rates low.

What I Learned

Key takeaways

Chunking strategy matters as much as the model you choose. Chunks that were too large diluted retrieval relevance, while chunks that were too small lost context — tuning chunk size and overlap had a bigger impact on answer quality than swapping LLMs.

Prompt design is where hallucination gets controlled. Explicitly instructing the model to answer only from the provided context, and to say when it doesn't know, made a bigger difference than any retrieval tweak. It also taught me how to think about evaluating a RAG system beyond just "does it sound right."
